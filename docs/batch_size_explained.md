# batch_size 파라미터 설명

## 개념

`batch_size`는 **텍스트가 분할된 후, 한 번에 몇 개의 세그먼트를 동시에 처리할지** 결정합니다.

## 동작 과정

### 1단계: 텍스트 분할
```python
입력: "안녕하세요, 유즈하입니다! 새로운 괴담 이야기를 해드릴까요?"

text_split_method: "cut5" 적용
↓
세그먼트 생성:
- 세그먼트 1: "안녕하세요,"
- 세그먼트 2: "유즈하입니다!"
- 세그먼트 3: "새로운 괴담 이야기를 해드릴까요?"
```

### 2단계: 배치 처리

#### batch_size = 1 (현재 설정)
```python
[세그먼트 1] → GPU 처리 → 오디오 1
[세그먼트 2] → GPU 처리 → 오디오 2
[세그먼트 3] → GPU 처리 → 오디오 3

순차적 처리 (하나씩)
```

#### batch_size = 2
```python
[세그먼트 1, 세그먼트 2] → GPU 병렬 처리 → 오디오 1, 2
[세그먼트 3]             → GPU 처리       → 오디오 3

2개씩 묶어서 처리
```

#### batch_size = 3
```python
[세그먼트 1, 2, 3] → GPU 병렬 처리 → 오디오 1, 2, 3

모두 한 번에 처리
```

---

## batch_size 비교

### batch_size = 1 (현재) ⭐

**장점:**
- ✅ **가장 빠른 첫 응답** (TTFB 최소)
- ✅ 메모리 사용량 최소
- ✅ 스트리밍에 최적

**단점:**
- ❌ 전체 처리 시간은 더 길 수 있음 (여러 번 GPU 호출)

**적합한 경우:**
- 실시간 대화형 TTS
- 빠른 응답이 중요
- **스트리밍 모드** 사용 시

**예상 성능:**
```
텍스트: 3개 세그먼트
TTFB:   0.42초 (첫 세그먼트만)
전체:   1.40초 (0.42 + 0.50 + 0.48)
```

---

### batch_size = 2

**장점:**
- ✅ GPU 활용도 향상
- ✅ 전체 처리량(throughput) 증가

**단점:**
- ❌ TTFB 증가 (2개 모을 때까지 대기)
- ❌ 메모리 사용량 증가

**적합한 경우:**
- 긴 텍스트 생성
- 전체 처리 시간 최소화 중요

**예상 성능:**
```
텍스트: 3개 세그먼트
TTFB:   0.70초 (2개 처리)
전체:   1.20초 (0.70 + 0.50)
```

---

### batch_size = 4+

**장점:**
- ✅ 최대 처리량
- ✅ 긴 텍스트에 효율적

**단점:**
- ❌ TTFB 크게 증가
- ❌ 메모리 사용량 크게 증가
- ❌ 스트리밍 효과 감소

**적합한 경우:**
- 오프라인 대량 생성
- 긴 문서 변환
- 배치 작업

**예상 성능:**
```
텍스트: 8개 세그먼트
TTFB:   1.50초 (4개 처리)
전체:   3.00초 (1.50 + 1.50)
```

---

## 관련 파라미터

### batch_threshold (기본값: 0.75)
```python
batch_threshold: 0.75  # 배치 분할 임계값
```

**의미:**
- 세그먼트 길이가 크게 차이날 때 배치를 분할
- 0.75 = 75% 이상 차이나면 분리

**예시:**
```python
세그먼트 1: "안녕하세요" (6글자)
세그먼트 2: "안녕하세요, 저는 GPT-SoVITS를 사용하는 유즈하입니다" (30글자)

비율: 6/30 = 0.2 < 0.75
→ 다른 배치로 분할 (효율적 처리)
```

### split_bucket (기본값: True)
```python
split_bucket: True  # 배치를 버킷으로 분할
```

**의미:**
- 길이가 비슷한 세그먼트끼리 묶음
- GPU 패딩 최소화 → 효율 향상

## 실전 권장 설정

### 실시간 대화형 (현재 사용) ✅
```python
batch_size: 1
streaming_mode: 3  # 가장 빠른 스트리밍
```
→ **TTFB 최소화, 즉각 응답**

### 긴 텍스트 생성
```python
batch_size: 2
streaming_mode: False
```
→ **전체 처리 시간 단축**

### 오프라인 대량 생성
```python
batch_size: 4
streaming_mode: False
parallel_infer: True
```
→ **최대 처리량**

## 결론

### 현재 설정 (batch_size=1)이 최적인 이유:

1. ⚡ **TTFB 최소화** - 0.422초
2. 🎙️ **스트리밍에 완벽** - 실시간 응답
3. 💾 **메모리 효율적** - 최소 사용량
4. 🎯 **대화형 TTS에 이상적**

### batch_size 증가를 고려할 상황:

1. 긴 텍스트 (100문장 이상)
2. 오프라인 배치 작업
3. 전체 처리 시간이 중요
4. GPU 메모리 여유가 충분

### 권장:

**현재 설정 유지!** `batch_size=1`이 실시간 대화형 TTS에 최적입니다. ✅
