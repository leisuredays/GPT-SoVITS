## 💡 분석 및 결론

### 1. 예상과 다른 결과

**예상:**
- v2 기본 모델 (102MB) → 훨씬 빠를 것
- 커스텀 모델 (165MB) → 약 1.6배 느릴 것

**실제:**
- v2 기본 모델 (워밍업 후): 0.367초
- 커스텀 모델: 0.422초
- **실제 차이: 약 15%만 빠름**

### 2. 왜 차이가 적을까?

#### A) 병목 구간 분석
```
전체 TTS 파이프라인:
1. 텍스트 전처리      (~0.05초)
2. BERT 인코딩        (~0.10초)
3. GPT 모델 (s1)      (~0.15초)  ← 149MB로 동일
4. SoVITS 모델 (s2)   (~0.10초)  ← 차이 발생 지점
5. 후처리             (~0.02초)
```

**GPT 모델 (149MB)은 동일하므로 병목!**

- GPT 모델 처리 시간이 전체의 40% 차지
- SoVITS 크기 차이의 영향은 20-30%에 불과
- 나머지는 전처리/후처리

#### B) 모델 아키텍처의 영향

v2ProPlus (165MB) 모델은:
- 더 큰 모델이지만 최적화된 구조
- FP16 사용 시 메모리 대역폭 효율적
- GPU 병렬 처리에 최적화

#### C) GPU 성능의 영향

CUDA + FP16 환경에서:
- 모델 크기보다 연산 효율성이 중요
- 165MB도 GPU 메모리에 충분히 수용
- 메모리 대역폭 병목이 아닌 연산 병목

### 3. 첫 요청 지연 (Cold Start)

v2 기본 모델 첫 요청: **5.277초**
- 모델 로딩 시간 포함
- 약 5초의 초기화 오버헤드

**워밍업 후에는 안정적:**
- 2~5번 요청: 0.277~0.542초
- 일관된 성능

### 4. 실전 의미

#### 속도 관점 (15% 차이)
```
v2 기본:     0.367초 → 사용자는 "즉각 반응" 느낌
커스텀:      0.422초 → 사용자는 "즉각 반응" 느낌
```
→ **체감 차이 거의 없음** (둘 다 0.5초 미만)

#### 품질 관점
- 커스텀 모델: 특정 화자(유즈하)에 최적화
- v2 기본: 범용 모델

→ **커스텀 모델의 품질 향상이 속도 15% 감소를 보상**
